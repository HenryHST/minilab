# Home Assistant — Instanz `ha02.stadthagen.dev`

Ops-/Architektur-Notiz für **minilab**. Home Assistant läuft **nicht** als Workload in diesem GitOps-Repo, ist aber angebunden (DNS/Pangolin, Monitoring, Nutzerdoku).

## Kurzprofil

| Feld | Wert |
|------|------|
| Öffentliche / Nutzungs-URL | **https://ha02.stadthagen.dev** |
| Rolle | Zentrale Smart-Home-Steuerung (UI + Automationen) |
| Ownership Host / Exposure | **Infra_LAB / Terraform** (nicht Argo-App in `apps/`) |
| Pangolin-Site | **Stadthagen-pro** (LAN-Target `ha02`, siehe `apps/ops/pangolin-publish/README.md`) |
| DNS | Terraform `module.dns` (`ha02`, …) |
| Monitoring | Node-Exporter job `ha02-node` (`:9100`); HA entities job `homeassistant` → `:8123/api/prometheus` (Bearer); Grafana folder *Home Assistant* |
| Nutzerdoku (BookStack/Git) | [`docs/bookstack/books/home-assistant/`](../bookstack/books/home-assistant/) |

## Was in diesem Repo liegt

- Scrape-Jobs: [`apps/monitoring/kube-prometheus-stack/values.yaml`](../../apps/monitoring/kube-prometheus-stack/values.yaml) (`ha02-node`, `homeassistant`)
- Dashboard: [`manifests/dashboard-homeassistant.yaml`](../../apps/monitoring/kube-prometheus-stack/manifests/dashboard-homeassistant.yaml) (Sidecar, Folder *Home Assistant*)
- HA-Package (Infra_LAB): `ansible/playbooks/k3s_cluster/files/ha02/packages/prometheus.yaml`
- Token: SecretSpec `HA_PROMETHEUS_TOKEN` → Secret `monitoring/ha-prometheus-token`; Wizard `Infra_LAB/scripts/wizard-ha-prometheus.sh`
- Nutzungsanleitungen (Nicht-IT) unter BookStack-Buch *Home Assistant*
- **Keine** Deployment-Manifeste für HA selbst (kein `apps/home-assistant/`)

## Architektur (Einordnung)

```text
Nutzer (Browser/App)
    → https://ha02.stadthagen.dev
    → Pangolin (Site Stadthagen-pro) / DNS
    → Host ha02 (Home Assistant, typ. :8123)
         ↳ Zigbee / Matter / Homematic / Bluetooth / … (Integrationen auf dem Host)
```

Cluster-seitig (minilab k3s) wird HA nur **beobachtet** (Metriken), nicht betrieben. Öffentliche k3s-Apps (`idp`, `termix-ext`) laufen über Site **k3s** / `pangolin-publish` — das ist ein **anderer** Pfad als `ha02`.

## Voraussetzungen

### A) Damit Nutzer die UI nutzen können

| # | Voraussetzung | Hinweis |
|---|---------------|---------|
| 1 | Host **ha02** online, Home Assistant gestartet | Supervisor/OS/Container je nach Installationsart |
| 2 | DNS-Name `ha02.stadthagen.dev` zeigt auf den vorgesehenen Endpoint | Terraform DNS / Pangolin |
| 3 | Pangolin-Ressource (HTTP) für `ha02` auf Site **Stadthagen-pro** | Infra_LAB `module.pangolin_config` |
| 4 | TLS am Edge (Pangolin) gültig | Nutzer sehen kein Zertifikat-Warnung |
| 5 | Reverse-Proxy-Einstellungen in HA, falls nötig | `use_x_forwarded_for` / `trusted_proxies` (HA-Docs) |
| 6 | Mindestens ein Login (lokal und/oder IdP) | Konten für Haushaltsnutzer anlegen |
| 7 | Optional: Companion-App mit Base-URL `https://ha02.stadthagen.dev` | Siehe Buch-Kapitel *Anmelden & App* |

### B) Für Integrationen (nach Bedarf)

| Integration | Typische Voraussetzungen (Host/Umgebung) |
|-------------|------------------------------------------|
| **Zigbee** | USB-Coordinator oder Ethernet-Gateway; Integration ZHA oder Zigbee2MQTT; Mesh-fähige Router-Geräte |
| **Matter** | Matter-fähige Geräte; bei Thread: Border-Router; HA Matter-Server/Integration |
| **Homematic / Homematic IP** | CCU oder Access-Point erreichbar; HA-Integration; Funkreichweite |
| **Bluetooth / BLE** | BT-Adapter am HA-Host und/oder BLE-Proxies; begrenzte Reichweite |
| Weitere (WLAN-Geräte, Kameras, …) | Je Integration Netzwerkzugriff und Credentials |

### C) Betrieb & Observability (Homelab)

| # | Voraussetzung | In minilab |
|---|---------------|------------|
| 1 | Node-Exporter Addon auf ha02 Port **9100** | Job `ha02-node` |
| 2 | Package `prometheus:` + LLAT | Job `homeassistant` → `192.168.0.106:8123/api/prometheus` |
| 3 | Firewall erlaubt Scrapes vom Cluster auf `:9100` und `:8123` | sonst Target down |
| 4 | Backup der HA-Konfiguration / Snapshots | außerhalb dieses Repos organisieren |
| 5 | Status-Check in Gatus (empfohlen) | manuell in `status.stadthagen.dev` |
